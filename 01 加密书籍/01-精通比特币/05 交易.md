## 疑问及解答

1. 交易输入完成流程

```text
交易输入包含 outpoint
        │
        ▼
全节点用 txid 找到之前交易
        │
        ▼
用输出索引找到特定输出
        │
        ▼
检查该输出是否在 UTXO 数据库中
        │
        ├── 不在 → 无效（不存在或已花费）
        │
        ▼
在 → 获取金额、锁定脚本、确认信息
        │
        ▼
执行脚本，验证签名和条件
        │
        ▼
检查金额是否足够、是否双花
        │
        ▼
验证通过 → 接受交易
```

2. 什么是“带长度前缀的输入脚本字段”

   scriptSig 前面先用 CompactSize 写一个长度值，告诉解析器脚本有多少字节，然后才是脚本内容。空脚本的长度前缀是 0x00，非空脚本的长度前缀是对应字节数。解析器靠它知道脚本在哪里结束、sequence 从哪里开始。

3. 一个 32 位 sequence 字段的总结

```text
bit 31         bit 22              bit 15 ... bit 0
  │              │                      │
  │              │                      └── 锁定值（16 位）
  │              └── 类型标志：0=区块，1=秒
  └── 禁用标志：0=启用相对时间锁，1=禁用
```
